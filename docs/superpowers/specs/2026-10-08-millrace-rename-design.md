# Rename DSE to Millrace — design

Date: 2026-10-08. Status: approved by the owner (decisions below were each
chosen explicitly).

## Why

The project is about to be open-sourced from the owner's personal GitHub
account (copyright Creative Cod3 Pty Ltd, MIT). "DSE" is a known brand in the
same industrial space (Deep Sea Electronics, generator and genset
controllers), so the name invites confusion in exactly the audience the
project is for. The new name is **Millrace**: the channel that drives a mill
wheel. The rename ships as **1.1.0**, together with the unreleased Modbus/FUXA
work, as the first public release.

## Decisions

| Question | Decision |
|---|---|
| Depth | Full rename: solution, projects, folders, namespaces, assemblies, CLI, diagnostics, env vars, Docker, docs |
| Product name in prose | `Millrace` |
| CLI command | `millrace` (was `dse`) |
| Diagnostic codes | `MR` + the same three digits: `DSE001` → `MR001`, `DSE206` → `MR206`, `DSE900` → `MR900` |
| History documents | Rewritten too: `docs/superpowers/specs/*`, `docs/superpowers/plans/*` and every past `CHANGELOG.md` entry use the new names |
| Version | `1.1.0` |
| Git history, tags | Untouched. Tag `v1.0.0` stays where it is; commit messages keep the old name |

## Mapping

Every rule is **case-sensitive**. A case-insensitive or substring replace of
`dse` corrupts real identifiers: `SpeedSensor`, `ItemIdSequence`,
`elapsedSeconds`, `ElapsedSeconds`, `holdSeconds`, `AddSeconds`,
`TimedSeconds` and `SortedSet` all contain `dSe` or `dse` across a word joint,
and they must not change.

| Old | New | Where |
|---|---|---|
| `Dse.` (namespace, project, assembly, folder prefix) | `Millrace.` | `src/`, `tests/`, `.sln`, `.csproj`, `using`, docs |
| `Dse.sln` | `Millrace.sln` | root, README, docs, Dockerfile |
| `Dse` + a diagnostic number inside an identifier (`IsDse015`, `OnlyDse016`) | `Mr` + number (`IsMr015`, `OnlyMr016`) | test method and helper names |
| `Dse` as a product word inside an identifier (`DseValidate…`, `TheDseServer…`, `InDseControl…`) | `Millrace` (`MillraceValidate…`, `TheMillraceServer…`, `InMillraceControl…`) | test method names |
| `DSE` + three digits | `MR` + the same three digits | code, messages, goldens, docs |
| `DSE` (the product, in prose and comments) | `Millrace` | everywhere |
| `DSE_UPDATE_GOLDEN` | `MILLRACE_UPDATE_GOLDEN` | `tests/Shared/Golden.cs`, docs |
| `dse` (the command, as a whole word) | `millrace` | help text, usage, messages, docs, Docker `ENTRYPOINT`/`command` |
| `dse-plant.schema.json` | `millrace-plant.schema.json` | README, tests |
| `dse-run-`, `dse-cli-`, `dse-sample-`, `dse-map-` temp prefixes | `millrace-run-`, … | tests |
| `dse-dispatcher` thread name | `millrace-dispatcher` | `Millrace.Realtime` |
| Docker: project `dse-hmi`, service `dse`, image `dse-hmi/dse:local`, `/app/dse`, host `dse:5020`, `dse-hmi/fuxa:1.3.4-modbus` | `millrace-hmi`, `millrace`, `millrace-hmi/millrace:local`, `/app/millrace`, `millrace:5020`, `millrace-hmi/fuxa:1.3.4-modbus` | `hmi/fuxa/*` |
| `/home/keeper/Work/Github/POCs/DSE` (absolute paths in plan files) | the repository root, written as a relative path or "from the repository root" | `docs/superpowers/plans/*` |

The CLI's executable is `millrace` (the `AssemblyName` of `Millrace.Cli`).
Assemblies are `Millrace.<Area>`; `RootNamespace` follows. `Directory.Build.props`
gains `<Product>Millrace</Product>` and `Version` becomes `1.1.0`.

Diagnostics keep their numbers, meanings, ordering and documentation anchors
(anchors are renamed with the code: `#dse013` → `#mr013`). Output columns
padded to a code's width shrink by one character; that is expected and is
captured by regenerated goldens.

## What may keep the old name

Only these lines may still contain `DSE`, `Dse` or the word `dse` after the
rename:

1. This spec and the rename plan (they describe the rename).
2. `CHANGELOG.md`'s 1.1.0 entry, which states the rename.
3. One README sentence: "Millrace was called DSE up to 1.0.0."
4. Git history and the `v1.0.0` tag (not files).

The local checkout directory (`…/POCs/DSE`) and the GitHub repository name are
outside the tree; renaming the GitHub repository (`DSE` → `Millrace`, GitHub
keeps a redirect) is an outward-facing step the owner confirms after the merge,
followed by `git remote set-url`.

## Goldens

Golden files (`components-catalogue.json`, `control-catalogue.json`,
`plant.schema.json`, scenario and sample event logs, CLI output fixtures) are
regenerated with `MILLRACE_UPDATE_GOLDEN=1`, never hand-edited. Acceptance for
each regenerated golden: applying the mapping above to the old golden yields
the new golden byte for byte. Any other difference is a defect.

## FUXA HMI

`hmi/fuxa/mine-conveyors.fuxap.json` is regenerated by
`hmi/fuxa/generate-project.py` (from `millrace modbus-map --format fuxa`), not
hand-edited. FUXA tag addresses must not change: the rename touches names,
never register numbers.

## Acceptance

- `dotnet build Millrace.sln` clean with warnings as errors; `dotnet test
  Millrace.sln` passes the same **1718** tests (the count does not change; test
  names do).
- `git grep -n -e Dse -e DSE` and `git grep -n -w dse` find only the allowed
  lines above.
- The false-positive identifiers listed under Mapping are unchanged (same
  count of each before and after).
- Every golden obeys the golden rule above.
- `millrace --help`, `millrace validate samples/mine-conveyors/plant.json` and
  `millrace serve …` work; the README's commands run as written.
- `hmi/fuxa/smoke-check.sh` passes with `docker compose up --build` (when
  Docker is available; otherwise say so).
- `git log --follow` still traces a renamed file: folders and files are moved
  with `git mv`, and a moved file's content changes only by the mapping, so
  git's rename detection holds. Every commit builds and passes the tests.

## Out of scope

NuGet publishing, a CI workflow, `SECURITY.md`, `CONTRIBUTING.md`,
acknowledgements, and rewriting the two commits authored with the work email.
Those are separate open-source launch steps.
